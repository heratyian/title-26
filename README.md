# Title 26

A citation-grounded RAG assistant for exploring U.S. federal tax law.

Title 26 uses retrieval-augmented generation (RAG) to answer questions using the text of Title 26 of the United States Code (Internal Revenue Code) as context. Relevant sections of the tax code are retrieved from a vector database and provided to an LLM to generate an answer with source citations.

> **Note:** This project is for educational purposes and is not intended to provide professional tax advice.

## How it works

The project uses a simple RAG pipeline:

```text
Title 26 XML
    ↓
Parse and normalize
    ↓
JSONL dataset
    ↓
Generate embeddings
    ↓
Chroma vector store
    ↓
Retrieve relevant sections
    ↓
LLM
    ↓
Answer + U.S.C. citations
```

## Data source

The source data comes from the U.S. House of Representatives Office of the Law Revision Counsel:

[United States Code: Current Release](https://uscode.house.gov/download/download.shtml)

Download Title 26 in XML format and place it at:

```text
data/raw/usc26.xml
```

The XML is converted into a normalized JSONL dataset before being indexed.

## Requirements

- Python 3.10+
- [uv](https://docs.astral.sh/uv/)
- An OpenAI API key

## Setup

Clone the repository and install the dependencies:

```bash
git clone <repository-url>
cd title-26

uv sync
```

Create a `.env` file in the project root:

```text
OPENAI_API_KEY=your-api-key
```

Do not commit this file to source control.

## Build the dataset

After downloading the USC 26 XML file to `data/raw/usc26.xml`, convert it into the project's normalized JSONL representation:

```bash
uv run python scripts/build_dataset.py
```

This creates:

```text
data/processed/usc26.jsonl
```

Each record represents a section of Title 26 and includes metadata such as its section number, heading, and U.S.C. citation.

## Build the vector index

Create embeddings for the processed Title 26 data and store them in Chroma:

```bash
uv run python scripts/build_index.py
```

The resulting vector database is persisted locally and used by the RAG application for retrieval.

You only need to rebuild the index when the underlying dataset or indexing strategy changes.

## Ask a question

Once the index has been built, query Title 26 from the command line:

```bash
uv run title_26 "What is considered gross income?"
```

For example, the application may retrieve sections such as:

```text
26 U.S.C. § 61 — Gross income defined
```

and use those sections as context when generating its answer.

## Typical workflow

For a fresh installation:

```bash
# 1. Install dependencies
uv sync

# 2. Add data/raw/usc26.xml

# 3. Convert the XML into structured JSONL
uv run python scripts/build_dataset.py

# 4. Build the Chroma vector index
uv run python scripts/build_index.py

# 5. Ask questions
uv run title_26 "What is considered gross income?"
```

After the dataset and index have been built, you normally only need the final command:

```bash
uv run title_26 "Are gambling winnings taxable?"
```

## Development

The ingestion and query pipelines are intentionally separate:

- `build_dataset.py` converts the official U.S. Code XML into structured data.
- `build_index.py` converts that structured data into embeddings and stores them in Chroma vector database.
- `title_26` queries the existing vector store and uses retrieved sections to answer questions.

This separation makes it possible to experiment with chunking, embeddings, retrieval strategies, and LLMs without repeatedly parsing the original XML.
